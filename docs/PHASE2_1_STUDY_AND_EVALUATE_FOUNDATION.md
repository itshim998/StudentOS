# Phase 2.1 — Study and Evaluate Foundation

## Page purpose

Study and Evaluate is the student workspace that turns the generated Today plan into a concrete study flow. It sits between Academic Context and Studio in primary navigation. The page uses only the current day's generated TO-DO list and does not create placeholder tasks.

## TO-DO queue behavior

- When no current-day plan exists, the page asks the student to generate today's TO-DO list and links back to Today.
- The queue shows each real plan item's title, course when available, priority, suggested time, reason, and study status.
- Selecting an item opens its workspace and persists `Studying` on that item. Status is stored with the existing daily plan on the student profile, so no new table is required.
- Generated plan items receive stable IDs and begin as `Not started`. Existing saved plans are normalized when read.

## Material viewing behavior

The selected workspace looks for a linked generated material first, then an included Academic Context material related by course and task context.

- Generated text lessons render directly in the workspace.
- Linked web material opens in a new tab.
- Private uploaded PDFs use an authenticated, inline server response. Raw private file locations are never exposed to the browser.
- If no related material exists, the workspace offers **Generate study material**.

## Generated study material behavior

Study material generation uses the existing assistant execution path and the plan's weekly AI allowance. The same reservation and settlement behavior used by Today's plan applies:

- a successful lesson is charged at the existing tutoring-help cost;
- an unavailable generation is refunded and shows calm retry copy;
- an exhausted allowance shows the existing weekly-help limit message.

The lesson is concise and contains focus, core lesson, study steps, and a quick self-check. It does not create a strict test, answer key, score, timer, or submission action.

## Academic Context save behavior

A generated lesson is saved in the existing Academic Context material collection with the student, matched course when available, TO-DO item ID, topic/title, generation time, and generated text. Its origin is shown as **Generated by StudentOS**, keeping it distinct from uploaded PDFs and Classroom material. Existing permanent deletion removes it in the same way as another material.

No migration is required because source material records already retain their full payload and the daily plan already persists on the student profile.

## Mark study done behavior

**Mark study done** persists `Done` and a completion timestamp on the selected TO-DO item. The workspace confirms **Study marked done.** and reveals **Generate test**. In Phase 2.1 that button only displays **Test generation comes next.** No test session is created.

## Deferred work

Phase 2.2 is responsible for strict test generation and the test session experience. Phase 2.3 is responsible for final answer evaluation and later learning-state features. Learning Level, Consistency Points, flashcards, visual notes, timers, question papers, grading, submissions, Classroom writeback, and auto-submit are not part of this phase.
