# Phase 2.1B: Academic Context type semantics and PDF viewer

## Bug summary

Academic Context PDFs retained a broad uploaded-source identity, but Study and Evaluate did not consistently enforce the type selected at upload. A syllabus, assignment, or exam schedule could therefore win the same course/topic match used for a study handout. Private PDF opening also created an empty popup before the authenticated document request completed, which could leave `about:blank` visible or be blocked by the browser.

## Normalized Academic Context kinds

StudentOS now normalizes documents to:

- `syllabus`
- `study_material`
- `assignment`
- `exam_schedule`
- `generated_study_material`
- `unknown`

New uploads persist `contextKind` in the existing source-material payload. Legacy `artifactKind: material` maps to `study_material`. Generated lessons persist `generated_study_material`. Explicit stored fields take precedence; title inference is limited to old records without a recognized semantic value.

No database migration is required because source material payloads already retain additive fields.

## Study and Evaluate selection

Only `study_material` and `generated_study_material` can be selected as readable lesson material. Syllabi, assignments, exam schedules, and unknown documents are excluded from the general lesson matcher. When only planning context exists, the workspace explains that no study handout or notes are available and offers **Generate study material**.

This same matcher supplies strict-test generation and evaluation context, so planning-only documents are not silently promoted to lesson content there either.

## Planning context is preserved

Syllabi and exam schedules remain in Academic Context preparation and the prepared planning capsule. Today TO-DO generation, exam prioritization, and AI study-material generation retain access to that planning context. The change separates readable lessons from planning inputs; it does not remove context.

## Generated material behavior

Generated lessons are saved with `contextKind` and `materialKind` set to `generated_study_material`. They appear in **Study materials**, carry the **Generated by StudentOS** badge, and remain readable directly in Study and Evaluate.

## In-app PDF viewer

Uploaded Academic Context PDFs open in a modal inside StudentOS. The browser fetches the existing private inline endpoint with the signed-in session, creates a short-lived local object URL, and uses native PDF rendering. Raw private storage locations are never sent to the UI. Browsers without inline PDF support receive an **Open in new tab** fallback inside the viewer. Closing the viewer revokes the local object URL.

The viewer is available for uploaded syllabus, study material, assignment, and exam schedule PDFs. Study and Evaluate uses it only for actual uploaded study materials.

## Strict-test policy

Generated strict tests remain HTML rendered in the Study and Evaluate UI. No PDF viewer, download, print, or export path was added for test papers.
